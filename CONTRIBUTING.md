# Contributing

Open a focused issue or pull request. For checklist changes, explain the decision, industry/jurisdiction, source, failure case and how the question helps a reviewer. Keep general screening questions distinct from professional requirements.

Run `npm test`, `npm run check`, `npm run build`. Do not add dependencies or hosted data collection without a clear need. Do not submit real case files, credentials, personal data, client documents or unverified accusations. Use synthetic fixtures.

Catalog source is `src/catalog.mjs`. Keep `skills/due-diligence/references/domains.md` in sync with it. Cases use schemaVersion 1; preserve import/export compatibility or document a migration. Use text-safe rendering and validate references. No unknown-as-safe defaults or aggregate scores that hide material blockers.
