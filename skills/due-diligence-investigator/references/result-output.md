# Investigator output

Lead with the decision implication, scope actually checked and key limitations. Use the exact plan ID/revision. A partial package remains partial even if some tasks have strong evidence.

1. Decision memo: provisional recommendation, conditions, accountable human owner.
2. Task table: task ID / finding / source IDs and locations / hypothesis update / remaining uncertainty / changed action.
3. Evidence register: title, type, locator, dates, excerpt, verification performed, independence group and limits.
4. Material blockers and required checks not completed; counter-evidence and unresolved causal questions.
5. Usage ledger and budget left; null values and reasons for unmeasured time/spend.
6. Action table: action, owner/role, due date or decision gate, evidence needed to close.
7. Replan request: new evidence, affected task IDs, why the next investigation could change a decision, and budget already spent.
8. `dd-results/1` JSON when transferring to Scanner or another host, using the contained contract/example. The user transfers the plan/results across chats; no automatic cross-plugin messaging is installed.

Keep observations, claims, inferences, assumptions and hypotheticals distinguishable. “Source inspected” describes an action, not proof of authenticity. “Ready for human review” is never a transaction approval.
